# PNP-005 Gossip Mesh: Conformance Audit

> **Superseded.** This audit describes the tree at d8ceedb. Since then the implementation was brought to the spec and every MUST and SHOULD clause of PNP-005 got a conformance test that runs the code: `pnp_005_gossip.rs` and `pnp_005_mesh.rs` (with `pnp_005_sender_queue.rs` and `pnp_001_signaling_only.rs` for §5.10). The verdicts, line numbers and "Spec/code mismatches" below are the state before that work and are kept as the record of what was found. See the CHANGELOG entry "PNP-004 and PNP-005 conformance" for what changed and what is still open (the relay server's opt-in relay profile does not yet use the conformant relay node and descriptor gossip).

Read-only audit of the tree at commit d8ceedb, made by reading the spec (`specs/PNP-005-gossip-mesh.md`), the tests (`crates/parolnet-conformance/tests/pnp_005_gossip.rs` and `pnp_001_signaling_only.rs`) and the implementation. Nothing was built or run.

What the verdicts mean:

- **real:** the test calls the implementation and would fail if the clause were violated.
- **hollow:** the test is a tautology, checks only a constant, or re-implements the logic in the test body.
- **mis-pinned:** the test checks something other than the clause.
- **partial:** the test covers only part of the clause.
- **unimplemented:** no implementation was found, so the test is necessarily hollow.

What the Shipped? values mean:

- **no:** the gossip stack (`parolnet-mesh`) only runs in the relay server's non-default relay profile (`PeerManager`, parolnet-relay-server/src/main.rs:1403). The default signaling-only relay, `parolnet-app` and `parolnet-wasm` do not use it. `parolnet-core` is built without the `mesh` feature (workspace `default-features = false`).
- **library only:** code exists, but nothing calls it, not even the relay profile.

## Spec/code mismatches

- **MUST-003 and MUST-020: forwarded messages fail signature checks.**
  - `signable_bytes` hashes `ttl` (pg:248).
  - The forwarder decrements ttl (mg:488).
  - The next hop verifies the signature over the new ttl (mg:468-471).
  - So every non-anonymous message is rejected after its first hop. The spec contradicts itself here: MUST-003 excludes only sig, seen and hops from the signature, while section 5.2 has ttl changed at each hop. Test T5:211 pins ttl as covered.
- **MUST-011:** the code checks in this order (mg:362-472):
  1. decode (size, version)
  2. rate limit
  3. expiry
  4. future timestamp
  5. dedup
  6. PoW
  7. signature

  The spec order is version, expiry, TTL, signature, PoW, dedup, size.
- **MUST-009, 010:** anonymous envelopes are accepted for any payload type, and the signature check is skipped for them (mg:441; pg:190-197).
- **MUST-016, 046:** scoring and rate limiting are keyed on the claimed `src`, before the signature is verified (mg:379, mg:429-431, mg:445-447).
  - A forged src can penalize a victim or exhaust its budget.
  - All anonymous messages share one 10-per-minute bucket (PeerId 0).
- **MUST-021a:** the peer the message came from is never excluded. `process_gossip` has no from-peer parameter (mg:503-508).
- **MUST-023, 024:** a single jitter value is drawn after the sends have already happened (mg:516-536). It is never applied before forwarding and is not drawn per peer.
- **MUST-029:** when over 4 MB, only one message is evicted and the new one is pushed anyway (sf:166-171), so the buffer can exceed 4 MB.
- **MUST-030c:** eviction ties are broken by `stored_at`, not origination timestamp (sf:97).
- **MUST-031:** `PeerManager::add_peer` delivers stored messages at once, with no sync phase (pm:42-60).
- **MUST-032:** store expiry runs only in the 12-hour maintenance task (rs:1413).
- **MUST-033:** dedup uses a HashSet, not a bloom filter (mg:82-85). Functionally harmless.
- **MUST-038, 039:** the IBLT does not match the spec, and nothing calls `reconcile`.

  | | Spec | Code |
  |---|---|---|
  | Cells | 1024 | 80 / 400 / 2000 |
  | Hash functions | 3 | 3 / 4 |
  | Keys | 64-bit | 32-byte |
  | Encoding | CBOR maps | custom binary |

  Evidence: sync:20-55, sync:135-148, sync:263.
- **MUST-042, 043:** discovery is obfuscated UDP broadcast on port 19532, not mDNS (disc:1-18).
- **MUST-048:** the at-rest key is random per process, not derived from the identity key (sf:55-58). Only `encrypted_payload` is encrypted; the header (dest_peer_id) stays in clear.
