## Spec/code mismatches

1. The envelope `msg_type` travels in the cleartext header: crates/parolnet-protocol/src/envelope.rs:16 (`CleartextHeader.msg_type`) and crates/parolnet-core/src/envelope.rs:87-89. Relays can see Decoy (0x04), which contradicts MUST-013/014/015. PNP-001's header layout causes this, so it is also a conflict between specs.
2. The relay's default port is 9000: crates/parolnet-relay-server/src/main.rs:1205 `unwrap_or(9000)`. This contradicts MUST-034 and SHOULD-009.
3. Reconnect backoff starts at 1 s: crates/parolnet-app/src/signaling.rs:43 `BACKOFF_MIN = 1s`. This contradicts MUST-024 (30 s minimum).
4. TLS framing is a 4-byte length prefix, not HTTP/2: crates/parolnet-transport/src/tls_stream.rs:117-131. This contradicts MUST-035/036/037. `TlsTransport` also has no callers outside its crate.
5. ClientHello mimicry is incomplete: crates/parolnet-transport/src/tls_camouflage.rs:9-11 and :115-127 say extension order, groups and GREASE cannot be controlled with rustls. This contradicts MUST-029/030.
6. The cover page is only served in bridge mode: crates/parolnet-relay-server/src/main.rs:1716. A default relay does not serve the MUST-033/040 page.
7. PWA cover-traffic jitter uses `Math.random`: pwa/src/cover-traffic.js:33-37 ("Crypto rand isn't needed"). This contradicts MUST-020.
8. The PWA supports only NORMAL mode: pwa/src/cover-traffic.js:128-130 throws for any other mode. This contradicts MUST-001/002.
9. Cover traffic is off by default in every profile: pwa/src/settings.js:21 `coverTrafficEnabled = false`. This conflicts with MUST-004 and with §4.7's "Relay-profile deployments keep §4.3 unchanged".
10. The spec contradicts itself on interval vs jitter. §3 and §4.1 define the padding interval as the maximum gap between sends, while §4.4 adds jitter of 0..J_max to it. `StandardShaper::delay_before_send` (crates/parolnet-transport/src/noise.rs) follows §4.4, so the gap exceeds the §4.1 maximum.
