# PNP-003 Conformance Audit

> **Since this audit** (branch `test/conf-pnp-003`): the QR payload, the BootstrapHandshake, SAS verification, the hand-over to PNP-002 and the erasure rules are implemented in `parolnet-core` and the native client and have tests that run them; passphrase bootstrap and the discovery announcement exist as library code; mDNS, Bluetooth and the web client's side are open. See the "Pairing follows PNP-003" entry in `CHANGELOG.md`. The table below is the state before that work.

Read-only audit of the tree at commit 2bd86cd (the worktree HEAD; requested as d8ceedb), made by reading spec, tests and code (nothing was run).

Tests live in `crates/parolnet-conformance/tests/pnp_003_bootstrap.rs` (B). Implementation paths are relative to the repository root.

## Spec/code mismatches

1. **The QR text is hex, not base45 (MUST-007).** `crates/parolnet-app/src/engine.rs:737` (`hex::encode(&result.payload_bytes)`) and `crates/parolnet-wasm/src/lib.rs:1765` (`Ok(hex::encode(result.payload_bytes))`). `crates/parolnet-core/src/bootstrap.rs:85` says base45 is applied by the UI layer, but no base45 code exists anywhere.
2. **The desktop QR uses error-correction level L (MUST-008).** `apps/desktop/src/chat.rs:221`: `qrcode::QrCode::with_error_correction_level(data.as_bytes(), qrcode::EcLevel::L)`.
3. **The QR timestamp check has gaps (MUST-011).** `crates/parolnet-core/src/bootstrap.rs:127`: `if payload.ts > 0 && now_secs.saturating_sub(payload.ts) > QR_MAX_AGE_SECS`. A payload with ts = 0 skips the check, and future timestamps are never rejected.
4. **The QR payload map has an extra field.** `crates/parolnet-core/src/bootstrap.rs:21-22` adds an `rk` field (ratchet public key) that §3.1 does not define.
5. **Replay tracking does not match MUST-043.** `crates/parolnet-core/src/bootstrap.rs:219-229` (`NonceTracker::check_and_record`) has no 60-minute window, and at capacity it clears every recorded nonce, which re-opens replay. Nothing calls it.
6. **The §5.4 flow is skipped.** `crates/parolnet-core/src/envelope.rs:373-378` derives BS and calls `DoubleRatchetSession::initialize_responder(bs, ..)` directly: no BootstrapHandshake proof, no PreKeyBundle exchange, no PNP-002 handshake. `compute_bootstrap_proof`, `verify_bootstrap_proof` and `compute_sas` have no product caller.
7. **The scanner's identity key travels in clear (relevant to MUST-047).** `crates/parolnet-core/src/envelope.rs:362` takes it from `cleartext_header.source_hint`.
8. **A test contradicts the spec it claims.** B:227 derives BS with HKDF (salt = None, info = "parolnet-bootstrap"). The spec, and `derive_bootstrap_secret`, use salt = "ParolNet_bootstrap_v1", ikm = seed and info = the sorted identity keys.
