# PNP-009 conformance audit

Group Communication.

Read-only audit by a delegated reviewer (Opus), made by reading the spec, the tests and the code; nothing was run. The tree read was the worktree of branch `test/conformance-100` while it stood three commits after d8ceedb; those commits changed nothing in the code audited here except nine lines of `parolnet-relay-server/src/main.rs` (the idle-close fix). The implementing agent wrote this file from the reviewer's report and did not re-check the verdicts.

Test files, in `crates/parolnet-conformance/tests/`: `grp` = pnp_009_groups.rs, `sk` = pnp_009_sender_key.rs. Paths are relative to `crates/` unless they start with `pwa/`.

Verdicts: **real** (calls the implementation and would fail if it broke the clause), **partial**, **hollow** (tautology, constant-only, or the rule re-implemented in the test), **mis-pinned** (the test checks something else), **unimplemented** (no implementation found, so the test is necessarily hollow).

For the clauses the reviewer judged real, the report recorded only the id: their test location below comes from the `#[clause]` attributes (the line is that of the test `fn`), and where they are implemented and whether the shipped product does it were not recorded. The "Shipped?" cell of the other rows is derived mechanically from the "Implemented where" cell (not implemented: no; code in the relay binary; code in the legacy PWA; otherwise a library function whose use by a shipped path was not established), not from a separate check.

## Spec/code mismatches

As reported by the reviewer; not re-checked.

- MUST-029 / MUST-033: `SenderKeyState::rotate()` replaces the chain key and index and keeps the Ed25519 signing key (parolnet-crypto/src/sender_key.rs:267-276); the spec says rotation generates a new signing keypair.
- MUST-069: the group file hash check is `if computed != self.expected_hash` (parolnet-core/src/group_file.rs:203), not constant-time.
- MUST-020 to -024, MUST-071: nothing signs, verifies, admin-checks or version-checks a received `GroupOperation`. `GroupManager::add_member` / `remove_member` return `signature: Vec::new()` (group.rs:250-338) and no caller fills it; the PWA's GROUP_ADMIN handler (pwa/src/messaging.js:1474) does not verify either.
- MUST-019: `remove_member` checks only that the caller is an admin; it can remove the last admin (group.rs:297-319).
- MUST-026 / SHOULD-004: rotation is never automatic; only the removing admin rotates (group.rs:322) and `needs_rotation` is never called. `Group::new` sets `last_rotation_ts = 0` (group.rs:46), so `needs_rotation(now)` is true at once for real timestamps.
- MUST-037 / -038 / -040 / -001: the PWA group-text path does not use sender keys: it sends the plaintext object pairwise through `sendEnvelope` (pwa/src/messaging.js:563-575); flag 0x10 is set nowhere. The Rust sender-key path (`encrypt_group_text`, wasm `send_group_text`) does not pad.
- MUST-058: the camera pause during screen share exists only for 1:1 calls (parolnet-core/src/call.rs:293).
- MUST-072: `SenderKeyState` derives `Zeroize` with skipped fields and a manual `Drop`, not `ZeroizeOnDrop` (sender_key.rs:29-43, 295); the effect is the same, the letter of the clause and of CLAUDE.md invariant 2 is not met.
