# PNP-007 Media and File Transfer: conformance test audit

Read-only audit of the tree at commit d8ceedb, made by reading the spec (`specs/PNP-007-media-file-transfer.md`), the conformance tests and the code; nothing was built or run.

Test file abbreviations: `t007` = `crates/parolnet-conformance/tests/pnp_007_media_file.rs`, `sig` = `crates/parolnet-conformance/tests/pnp_001_signaling_only.rs`. Code paths are relative to the repository root.

## Counts

| Level | Clauses | Real | Weak (hollow / mis-pinned / partial / unimplemented) |
|---|---|---|---|
| MUST | 90 | 4 | 86 |
| SHOULD | 13 | 0 | 13 (SHOULD-013 has no test) |

General note: the spec's own Implementation Note (spec line 30) says the design is not what ships. Shipped calls are peer-to-peer WebRTC with DTLS-SRTP (crates/parolnet-app/src/call.rs, crates/parolnet-rtc, pwa/src/call.js). They do not use onion circuits, MediaCall shaping, or SRTP keyed from the Double Ratchet. `BandwidthMode::MediaCall` has no consumer.

## Spec/code mismatches

1. The envelope `msg_type` travels in the cleartext header: crates/parolnet-protocol/src/envelope.rs:16 and crates/parolnet-core/src/envelope.rs:87-89. Relays can see Audio (0x07), Video (0x08) and FileChunk (0x09), which contradicts MUST-085/089. PNP-001's header layout causes this, so it is also a conflict between specs.
2. Relays discard MEDIA_DATA cells: `StandardRelayNode::handle_cell` sends MediaData to `_ => Discard` (crates/parolnet-relay/src/relay_node.rs:226). This contradicts MUST-003.
3. The spec contradicts itself: a separate MEDIA_DATA cell type in the relay-visible cell header (crates/parolnet-relay/src/lib.rs:67) tells relays the cell is media. MUST-002 therefore conflicts with MUST-001/085.
4. Calls use DTLS-SRTP on P2P WebRTC: crates/parolnet-app/src/call.rs:4-6 ("DTLS-SRTP is end to end"), crates/parolnet-rtc, pwa/src/call.js. This contradicts MUST-012/014/015/053 and the MUST-001 premise that calls ride onion circuits.
5. Video is encoded in Rust: crates/parolnet-media/src/vp8 and apps/desktop. This contradicts MUST-027.
6. Only Opus and VP8 are offered: crates/parolnet-rtc/src/lib.rs:511-540 registers no Codec2 and no VP9. This contradicts MUST-016 and SHOULD-005.
7. RTP packets are larger than a relay cell: crates/parolnet-rtc/src/lib.rs:134 `RTP_OUTBOUND_MTU = 1200`, against the 457 B cell payload of MUST-032/033.
8. Keyframe requests are RTCP PLI sent on decode error, rate-limited to 1 s: crates/parolnet-rtc/src/lib.rs:942 and apps/desktop/src/receiver.rs:267. The spec wants a CALL_SIGNAL on >5% loss, sent immediately (MUST-037/039).
9. The native ring timeout is 60 s: crates/parolnet-app/src/engine.rs:65 `CALL_RING_TIMEOUT = 60s`, against 30 s in MUST-007/008. Only the core `CALL_TIMEOUT` (crates/parolnet-core/src/call.rs) is 30 s, and that is all the test checks.
10. A second call is never rejected: crates/parolnet-core/src/call.rs `start_call` / `incoming_call` accept a new call while one is Active. This contradicts MUST-070.
11. The jitter buffer is fixed at 40 / 300 ms and not configurable: crates/parolnet-media/src/duplex.rs:51-55. This contradicts MUST-020 (50-200 ms) and SHOULD-003 (100 ms initial).
12. Desktop video bitrate is 900 / 1800 kbps: apps/desktop/src/call.rs:51-53. This contradicts SHOULD-009 (150-500 kbps).
13. File hashes are compared with `!=`, not constant-time: crates/parolnet-core/src/file_transfer.rs:181 `computed != self.offer.sha256` and crates/parolnet-core/src/group_file.rs:203 `computed != self.expected_hash`. This contradicts MUST-062 and project security invariant 5. The test at t007:438 does its own `subtle` comparison and passes regardless.
14. An empty file counts as 1 chunk: `FileOffer::total_chunks` returns 1 for file_size 0 (crates/parolnet-protocol/src/file.rs:48-52), while the MUST-066 formula gives ceil(0) = 0. Minor, and not mentioned in the spec.
15. File chunks overflow the 4096 B envelope bucket: pwa/src/messaging.js:904-911 JSON-encodes each 4096 B chunk as a number array, roughly 15 KB. That defeats the rationale of MUST-055, which sizes chunks to fit the 4096 B bucket.
