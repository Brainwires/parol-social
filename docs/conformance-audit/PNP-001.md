# PNP-001 conformance audit

Read by the implementing agent itself, on branch `test/conformance-100` (based on d8ceedb), after the tests that branch adds. Verdicts come from reading the spec text, the test and the code; the tests named "added on this branch" were also run.

Test files, in `crates/parolnet-conformance/tests/`: `wire` = pnp_001_wire.rs, `flow` = pnp_001_envelope_flow.rs, `outer` = pnp_001_outer_frame.rs, `sig` = pnp_001_signaling_only.rs, `cb` = pnp_001_channel_binding.rs, `ice` = pnp_001_client_ice.rs, `direct` = pnp_001_direct_channel.rs, `relaybin` = pnp_001_relay_binary.rs, `nonce` = pnp_001_session_nonce.rs. Line numbers are those of d8ceedb for the old files.

How much of each file was read: `wire` lines 1 to 950 in full and the fragment tests by name and clause list; `flow` in full; `outer` lines 40 to 200 and 420 to 598 (the bootstrap tests at 287 to 420 by name only); `sig` lines 1 to 120 in full, the rest by name and imports; `cb` and `ice` by name and imports only. A verdict that rests on names and imports is marked "(not read)".

Verdicts: **real** (calls the implementation and would fail if it broke the clause), **partial**, **hollow** (tautology, constant, or the rule re-implemented in the test), **mis-pinned** (checks something else), **unimplemented** (no implementation found), **no test**.

## Spec/code mismatches

- §3.3 plaintext map (`body`, `chain`, `flags`, `seq`): not implemented. `encrypt_into_envelope` (parolnet-core/src/envelope.rs:98-102) encrypts the caller's bytes as they are. `PayloadContent` (parolnet-protocol/src/envelope.rs:175) is unused and still has a `pad` field.
- §3.9 fragmentation: `parolnet_core::fragmentation` has no caller outside tests; an over-size body is refused.
- MUST-005 against PNP-009: `MessageFlags::set_group` (parolnet-protocol/src/message.rs) uses bit 4.
- MUST-019: the decoy type code is in the cleartext header by this spec's own §3.2 layout.
- MUST-039: no freshness window on receive; the sender-side queue (PNP-005 §5.10) depends on there being none.
- MUST-042: `send_n` is a `u32` incremented without a check (parolnet-crypto/src/double_ratchet.rs, `self.send_n += 1`).
- MUST-003: the receive path decodes with `CborCodec::decode`, which does not check `version`; only `decode_header` does.
- SHOULD-014 (fixed on this branch): the relay counted WebSocket pongs as client frames, so the idle close never fired.
