# PNP-004 Relay Circuit: Conformance Audit

> **Superseded.** This audit describes the tree at d8ceedb. Since then the implementation was brought to the spec and every MUST and SHOULD clause of PNP-004 got a conformance test that runs the code: `pnp_004_relay_circuit.rs`, `pnp_004_circuit_network.rs` and `pnp_004_directory.rs`. The verdicts, line numbers and "Spec/code mismatches" below are the state before that work and are kept as the record of what was found. See the CHANGELOG entry "PNP-004 and PNP-005 conformance" for what changed and what is still open (the relay server's opt-in relay profile does not yet use the conformant relay node and descriptor gossip).

Read-only audit of the tree at commit d8ceedb, made by reading the spec (`specs/PNP-004-relay-circuit.md`), the tests (`crates/parolnet-conformance/tests/pnp_004_relay_circuit.rs`) and the implementation. Nothing was built or run.

What the verdicts mean:

- **real:** the test calls the implementation and would fail if the clause were violated.
- **hollow:** the test is a tautology, checks only a constant, or re-implements the logic in the test body.
- **mis-pinned:** the test checks something other than the clause.
- **partial:** the test covers only part of the clause.
- **unimplemented:** no implementation was found, so the test is necessarily hollow.

What the Shipped? values mean:

- **library only:** code exists in `parolnet-relay`, but no product calls it. No product path builds or relays onion circuits:
  - `parolnet-app` and `parolnet-wasm` build `parolnet-core` without the `native` feature, which is the one that pulls in `parolnet-relay`.
  - The relay server never instantiates `StandardRelayNode` or `StandardCircuitBuilder`.
- **no:** nothing implements the clause, or only the non-default relay profile does.

## Spec/code mismatches

- **MUST-002:** short payloads are zero-padded, not randomly padded.
  - circ:147, circ:203, circ:352
  - rn:165
  - hs:31, hs:64, hs:129, hs:172
- **MUST-024:** the AEAD tag is appended, not prepended. RustCrypto ChaCha20-Poly1305 outputs ciphertext then tag, and the onion:99 comment says so. The onion:71 doc wrongly says "prepended".
- **MUST-011, 025, 036, 052 (PADDING):**
  - Relays discard PADDING without decrypting or forwarding it (rn:115-118).
  - `RelayCell::padding` is never onion-encrypted (lib:144-153).
  - The cell type is a cleartext header byte. The spec's own section 3.1 layout puts it there, so MUST-025 is also in tension with the spec itself.
- **MUST-035:**
  - DATA on an unknown CID returns `Err(CircuitNotFound)` (rn:143-145).
  - EXTEND on an unknown CID is forwarded (rn:200-223).
- **MUST-005, 006, 008, 031 (EXTEND):**
  - The OP onion-encrypts the EXTEND payload (circ:201), but the relay parses it without peeling the layer (rn:209).
  - The relay forwards the same cell with the same CID instead of sending a CREATE on a new CID (rn:220-223).
  - An unknown PeerId returns Err, not DESTROY (rn:213-218).
- **MUST-033:** the circuit table is keyed by CID only, not (connection, CID) (rn:38).
- **MUST-034:** a CREATE on an existing CID silently overwrites that circuit (rn:81).
- **MUST-054, 055:** `MAX_RELAY_EARLY` = 8 is a per-circuit count-up. There is no hop counter in the cell, and EXTEND is treated like RELAY_EARLY (rn:18, rn:196-205).
- **MUST-019, 056:** at u32::MAX the code returns NonceOverflow but does not destroy the circuit.
  - rn:148-150
  - circ:63-66, circ:94-97
- **MUST-020:**
  - A failed key confirmation returns Err with no DESTROY (circ:340).
  - `extended_cell` / `process_extended` carry and check no key confirmation (hs:171-199), although section 3.6 says EXTENDED has the CREATED format.
- **MUST-016:** `StandardCircuitBuilder::build_circuit` does DH against the relay's long-term x25519_key and sends no CREATE (circ:289-302, circ:406-409).
- **MUST-030:** CID = `random | 1` (circ:320, circ:412), so CIDs are always odd and carry 31 random bits.
- **MUST-048:** DESTROY forwarding never fires in practice. The CREATE path always registers next_hop = None (rn:192), and no code sets Some.
- **MUST-041, 042, 043:**
  - The relay server never creates or signs its own descriptor; `create_descriptor` is called only in tests.
  - Descriptors travel over HTTP `/directory` and `/directory/push` (parolnet-relay-server/src/main.rs:240-330, ~893-1010), not over PNP-005 gossip.
  - `DESCRIPTOR_REFRESH_SECS` is unused (dir:33).
- **MUST-044:**
  - `handle_gossip_descriptor` does not check PeerId == SHA-256(identity_key) (dir:504-532).
  - `handle_signed_directory` and `handle_endorsed_descriptor` insert descriptors without per-descriptor signature or PeerId checks (dir:538-572).
- **MUST-047:**
  - `select_random` falls back to same-subnet candidates (dir:435-440).
  - IPv6 addresses are compared on their first 2 bytes, not a /48 prefix (dir:70-71).
- **SHOULD-004:** `select_path` calls `select_guards(1)`, which overwrites the guard set to size 1 (dir:625, dir:396). There is no 30-day stability tracking.
- **MUST-009:** DATA payloads have no Stream ID / command / length header (circ:143-156).
