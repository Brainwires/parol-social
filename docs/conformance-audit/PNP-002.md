## Spec/code mismatches

1. **`spk_id` is never checked (MUST-012).** `crates/parolnet-crypto/src/x3dh.rs::respond` (lines about 146-190) never reads `header.signed_prekey_id`. The caller supplies the SPK secret, and a mismatch silently yields a wrong SK. The test at H:433 documents this behaviour.
2. **Sessions are not set up through §5.** `crates/parolnet-core/src/envelope.rs:373-378` derives the PNP-003 bootstrap secret and calls `DoubleRatchetSession::initialize_responder(bs, ..)` directly. There is no HandshakeInit or HandshakeResponse, no `aead_algo`, no init key and no X3DH. `X3dhKeyAgreement` and `HandshakeStateMachine` are called only by tests.
3. **The initiator's identity key travels in clear (SHOULD-008).** `crates/parolnet-core/src/envelope.rs:362` reads the scanner's identity key from `cleartext_header.source_hint`.
4. **The MUST-012 test contains dead code.** `bob_signer_from` at H:464 is a placeholder, so the test's "correct path" check is never performed.
