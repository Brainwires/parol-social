# ParolNet Protocol Specifications — Index

**Last-Updated:** 2026-11-21

This index is the authoritative registry of ParolNet Protocol (PNP) specifications. The registry table and the date above are generated by `cargo xtask clauses --report` from the spec files and the conformance tests; hand-edits to them are overwritten, and CI fails when they are out of date (`cargo xtask clauses --check-index`). The `Coverage` column gives, per level, how many clauses are named by at least one `#[clause(...)]` test in `crates/parolnet-conformance` (`M` MUST, `S` SHOULD, `MAY`).

The gate (`cargo xtask clauses --check`) requires a test for every MUST and every SHOULD clause, and that every `#[clause]` id is one a spec publishes. CI runs the report without `--check` for now: many of the tests the column counts do not exercise the implementation (`docs/conformance-audit/`), and the gate goes back on when the coverage is real. MAY clauses are reported and not required: an implementation need not take an option, and an option it does not take has nothing to test.

The tool counts a clause as covered when a test names it. It cannot tell whether that test would fail if the implementation broke the clause; that is a matter for review.

## Clause ID Grammar

```
clause_id := "PNP-" spec_num "-" level "-" serial
spec_num  := 3 ASCII digits
level     := "MUST" | "SHOULD" | "MAY"
serial    := 3 ASCII digits, unique within (spec_num, level)
```

Clause IDs are stable. Once a clause ID is published in a CANDIDATE or ADOPTED spec it MUST NOT be recycled, reassigned, or silently removed. If a clause is superseded it is marked `[DEPRECATED]` in-place, directly after its id (`**PNP-001-MUST-042** [DEPRECATED]`), and the replacement receives a new serial. A deprecated clause is no longer normative: the tooling does not count it and requires no test for it.

## Status Lifecycle

| Status | Meaning |
|--------|---------|
| DRAFT | Incomplete or actively restructuring; not suitable for conformance testing. |
| CANDIDATE | Clauses stable enough to be pinned by conformance tests. Changes require version bump + changelog. |
| ADOPTED | Ratified with 100% MUST and 100% SHOULD coverage; wire-incompatible changes forbidden. |
| SUPERSEDED | Replaced by a later PNP; retained for historical reference. |
